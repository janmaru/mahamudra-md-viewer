# Internationalization (i18n) System

This application supports multiple languages via an i18n configuration system.

## 🌍 Supported Languages

- **en** - English (default)
- **it** - Italiano

## 🚀 Usage

### Launch with Language Parameter

```bash
# English (default)
python md_reader.py

# English (explicit)
python md_reader.py --lang en

# Italian
python md_reader.py --lang it
```

### Help

```bash
python md_reader.py --help
```

## 📁 Structure

```
i18n/
├── __init__.py      # I18nManager class
├── en.json          # English translations
└── it.json          # Italian translations
```

## 🛠️ Architecture

### I18nManager

The `I18nManager` class in `i18n/__init__.py` handles:

- **Loading translations** from JSON files
- **Fallback to English** if a key is missing in the target language
- **Runtime language switching** (optional)
- **String interpolation** with format arguments

### Key Features

✅ **Fallback Support**: If a key isn't found in Italian, English version is used  
✅ **String Formatting**: Supports placeholder substitution with kwargs  
✅ **Easy Access**: Global instance via `get_i18n().t("key")`  
✅ **Extensible**: Add new languages by creating new JSON files  

## 💻 Using Translations in Code

### In AppContext

```python
from app_context import AppContext

# Access via context
ctx.i18n.t("menu.file")        # → "File"
ctx.i18n.t("error.file_not_found", path="/some/file")
```

### Direct Access

```python
from i18n import get_i18n

i18n = get_i18n()
text = i18n.t("btn.open")       # → "Open" or "Apri" based on language
```

### With Format Args

```python
i18n.t("status.lines", count=42)  # → "Lines: 42" or "Righe: 42"
```

## 📝 Adding New Translations

1. **Identify all hardcoded UI strings** in the codebase
2. **Add them to** `i18n/en.json` with descriptive keys:
   ```json
   {
     "menu.file": "File",
     "btn.open": "Open",
     ...
   }
   ```
3. **Translate to Italian** in `i18n/it.json`:
   ```json
   {
     "menu.file": "File",
     "btn.open": "Apri",
     ...
   }
   ```
4. **Update code** to use `ctx.i18n.t("key")` instead of hardcoded strings

## 🔄 Translation Workflow

### Namespace Convention

Use dot notation for key organization:

- `menu.*` - Menu items
- `btn.*` - Button labels
- `dialog.*` - Dialog titles/messages
- `error.*` - Error messages
- `success.*` - Success messages
- `toast.*` - Toast notifications
- `status.*` - Status bar text
- `shortcuts.*` - Keyboard shortcuts

### Example Keys

```json
{
  "menu.file": "File",
  "menu.open_file": "Open File...",
  "btn.open": "Open",
  "btn.cancel": "Cancel",
  "dialog.error": "Error",
  "error.file_not_found": "File not found: {path}",
  "success.saved": "File saved successfully"
}
```

## 🌐 Adding a New Language

1. Create `i18n/{lang_code}.json` with the same keys as `en.json`
2. Update `md_reader.py` argparse choices:
   ```python
   parser.add_argument("--lang", choices=["en", "it", "es", ...])
   ```
3. Translate all strings in the new JSON file

## ✨ Best Practices

1. **Always provide English fallback** - Never leave English translations blank
2. **Use descriptive keys** - `menu.file` is better than `m1`
3. **Group related strings** - Use namespace prefixes
4. **Support string formatting** - Use `{placeholder}` for dynamic values
5. **Keep JSON files in sync** - Both language files should have identical keys
6. **Test before committing** - Verify both languages work correctly

## 🧪 Testing

### Check Available Languages

```python
from i18n import I18nManager
mgr = I18nManager("en")
print(mgr.get_available_languages())  # → ['en', 'it']
```

### Test Translation

```python
from i18n import I18nManager
mgr = I18nManager("it")
print(mgr.t("menu.file"))  # → "File" or falls back to English
```

### Runtime Language Switch

```python
from i18n import get_i18n
i18n = get_i18n()
i18n.set_language("it")
print(i18n.t("menu.file"))  # → Italian version
```
